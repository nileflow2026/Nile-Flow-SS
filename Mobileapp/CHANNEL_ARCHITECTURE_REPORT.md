## Channel Definitions

| Channel       | Purpose                           | Distribution              | Branch    | OTA Enabled |
| ------------- | --------------------------------- | ------------------------- | --------- | ----------- |
| `development` | Daily development builds          | Internal (dev team)       | `develop` | Yes         |
| `staging`     | QA and integration testing        | Internal (QA team)        | `staging` | Yes         |
| `preview`     | UAT, demo, stakeholder review     | Internal (select testers) | `preview` | Yes         |
| `production`  | App Store and Play Store releases | Public                    | `main`    | Yes         |

## Promotion Workflow

1. **develop → staging:** Auto-deploy via `deploy-staging.yml` workflow when
   code is merged to `develop` or `staging` branches.
2. **staging → preview:** Manual promotion after QA sign-off. Run `eas update`
   targeting the `preview` channel.
3. **preview → production:** Approval-gated via `deploy-production.yml` workflow
   with environment protection rules. Requires production approval gate.

## Channel Naming Convention

- All lowercase
- Descriptive of environment
- Matches EAS profile name
- Matches git branch name where possible
